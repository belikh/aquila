## Systemic root causes

1. **Within-phase parallel fan-out on shared, mutable state.** All 19 specification agents were launched inside ~3 minutes, and all five L1 crates inside ~10 seconds, against one working tree with no per-agent worktree and no frozen baseline. Specs named the same concepts differently (five named divergences plus port conflicts, per ADR-0003); implementers then observed each other's half-written files ("concurrent editor"). The reconciliation cost landed on a later agent and on the implementers themselves.

2. **Hidden per-agent scope restrictions standing in for a settled interface.** Prompts encode "edit ONLY this crate", "do NOT add dependencies", "do NOT create GitHub issues", "do NOT commit", "no `cargo update`", "do not add the `ort` dependency". Where the settled interface or artefact was *missing*, those restrictions made the correct action impossible, so agents did the nearest permitted thing: a provisional `FeatureVector`, a duplicated `CsiFrame`, a per-crate SHA-256, JSON instead of TOML, a gated stub, a missing `node_wire.h` array, or a hand-written bridge. The restrictions were enforced harder than the interfaces were frozen.

3. **The environment was provisioned per-phase and incompletely, and its definition changed mid-project.** The prescribed builder `shell.nix` lacked the `wasm32` target and bundler that `dashboard.md` requires; Python lacked HA/PyYAML; the workspace lacked `sha2`/a TOML crate; the analysis corpus lacked `node_modules` and full git history. The corrective environment (`flake.nix` with wasm32 + trunk) exists on disk but is **staged, not committed**, so it is invisible to the next agent and to CI.

4. **Declared-but-absent artefacts act as traps.** `aquila-api`, `aquila-ha`, `aquila-addon`, `xtask` and `tools/dag.toml` are all named in the interface register as if they exist; `aquila-evaluation` is a 2-line stub. Agents told to depend on or "keep valid" these were blocked or silently substituted.

## The single highest-value fix

**Freeze the interface and the toolchain in one *committed* baseline before any implementation fan-out, then dispatch implementers against that commit — sequentially, or in isolated worktrees.** Concretely: commit the staged `flake.nix`/`flake.lock` (wasm32 + trunk + wasm-bindgen) so the dashboard is buildable at all; move `FeatureVector` into `aquila-types` and settle one `CsiFrame` and one on-air layout; add `tools/dag.toml` + `xtask`; and either scaffold `aquila-api`/`aquila-ha`/`aquila-addon` or strike them from the register. Then re-dispatch ticket #10 (dashboard), whose abort is the single largest concrete loss (an entire v1 deliverable, three omissions deep).

This one change removes the causes behind #1, #2, #9, #11, #13, #16, #21 and #23 simultaneously: a frozen, single-source-of-truth commit makes the scope restrictions safe, gives every agent a clean baseline, and guarantees the toolchain the prompts assume is actually present.
